# 拾光 Img2Prompt

Chrome 扩展：右键网页图片、拖入本地图片或粘贴截图，一键反推出**中英双语**的图片提示词，可直接粘贴到文生图工具里使用。

<p align="center">
  <b>Manifest V3</b> · 无后端 · 数据不出本机 · 支持 Chrome / Edge / Brave
</p>

---

## 特性

- **三种触发方式**：右键网页图片、拖入本地图片、粘贴截图（各有开关，默认只开右键）
- **中英双语输出**：每一项描述都同时给出中文和英文，适配国内与海外的文生图工具
- **多套提示词方案**：内置一套经过调校的方案，可自建多套按需切换
- **识别真实原图**：不只拿网页上的缩略图，会尽力回溯到原图地址
- **比例自动识别**：识别到标准比例时写入提示词；识别不到就不写，不硬猜
- **历史与收藏**：同一张图多次反推会保留全部结果，可来回对比
- **结果可编辑**：提示词在面板里可直接改，改完能存为收藏
- **反推后自动复制**：可开启，反推完成即写入剪贴板

## 安装

### 从源码安装

1. 打开 `chrome://extensions`（Edge是 `edge://extensions`）
2. 右上角开启「**开发者模式**」
3. 点「**加载已解压的扩展程序**」，选择本仓库根目录
4. 点击扩展图标 → 选择视觉模型 → 填入 API Key → 点「测试连接」

> 改了代码后必须点扩展卡片上的刷新按钮，再刷新页面才生效。这是「改了没反应」最常见的原因。

### 可安装的浏览器

Chrome 105+ / Edge 105+ / Brave / Opera / Arc 等基于 Chromium 的浏览器。Firefox 暂不支持（Manifest V3 的 API 差异）。

## 配置

### 两个概念要先分清

插件里有两个独立的选择，作用完全不同：

| | 干什么 | 可选值 |
|---|---|---|
| **视觉模型** | 负责**看图**，产出结构化描述 | Agnes（默认）/ DeepSeek / Gemini |
| **输出引擎** | 负责**组装**，决定提示词写成什么句式 | Nano Banana（默认）/ Seedance |

换视觉模型只影响识别准不准；换输出引擎只影响提示词长什么样。两者可以自由组合。

### 支持的视觉模型

| 视觉模型 | 接口协议 | 说明 |
|---|---|---|
| **Agnes** | OpenAI 兼容 | 默认推荐，原生图像理解 |
| **DeepSeek** | OpenAI 兼容 | 便宜，模型 ID 以控制台实际可用的为准 |
| **Gemini** | Gemini 原生 | 与 Nano Banana 共用一个 key |

API Key 存在浏览器本地（`chrome.storage.local`），按服务商分开存放，互不覆盖。**不会上传到任何第三方服务器**，只在调用模型接口时随请求发出。

设置页还支持一键导出 / 导入全部设置，换机或重装时可以恢复（历史与收藏不含在内）。

## 用法

| 方式 | 操作 | 默认 |
|---|---|---|
| 右键 | 页面上右键图片 → 「拾光 · 反推提示词」 | ✅ 开 |
| 拖拽 | 把图片拖到网页的角落投放区 | ❌ 关 |
| 粘贴 | 在任意网页按自定义快捷键粘贴截图 | ❌ 关 |

拖拽和粘贴默认关闭，因为它们会介入页面原有的交互。需要时在设置页打开。

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `Alt+Shift+P` | 切换到下一个提示词方案 |
| `Alt+Shift+C` | 复制当前面板里的提示词 |
| 自定义 | 「快捷键粘贴」触发方式所用的组合键 |

前两个可在 `chrome://extensions/shortcuts` 里改。

### 面板

点扩展图标可以打开结果面板。面板里可以：

- 顶部大图预览，**点图片看原图**
- 英文 / 中文两个提示词框，内容可直接编辑
- 同一张图多次反推的结果以缩略图网格平铺，点击切换对比
- 底部折叠区是「我的收藏」和「历史记录」

**网格交互**：左键打开详情，右键直接复制提示词（收藏和历史都适用）。

## 工作原理

```
取图层  定位命中的图片 → 尽力回溯原图 → 降采样到长边 1024
字段层  视觉模型看图 → 结构化字段（每项都有 en + zh 两份）
渲染层  按输出引擎组装成对应句式的提示词
```

字段层不含引擎特定语法，所以两个渲染器各自只负责「组装 + 语言 + 比例处理 + 约束处理」。**加一个新引擎只需要写一个新渲染器**，不用动前两层。

### 比例是怎么处理的

比例识别基于图片真实宽高，把最接近的标准比例写进提示词。有两条原则：

1. **不猜**。所有候选都不够接近时不写比例，而不是塞一个最像的 ——
   强行给出偏差很大的比例，比不给更糟。
2. **判据来自数据而非魔数**。每个候选的容差取它到相邻候选分界点的距离 ——
   因为相邻比例的间距差别很大（`3:4`↔`4:5` 只隔 3.3%，而 `16:9`↔`21:9` 隔 14.6%），
   用同一个阈值必然一边过宽、一边过窄。

### 取图为什么这么绕

浏览器扩展取图有个隐蔽的坑：`chrome.scripting.executeScript` 注入的脚本**内部抛错时不会 reject**，
它照样 resolve —— 于是「注入成功」的假象掩盖了「监听器根本没注册」。

所以取图不用消息通道，而是让函数直接在页面上下文执行完返回结果。配套还有几个必要设计：

- **用元素标记定位而非坐标**：坐标方案在 iframe 和 shadow DOM 里会失效
- **必须 `allFrames`**：图片常在 iframe 里，只查主框架会「点哪张都是同一张」
- **锁定同一个 frameId**：定位可以多 frame 竞争，取像素必须锁定，否则子框架的兜底结果会污染选择

面板在取图失败时会显示每一级取图方式各自失败的原因，便于排查。

## 隐私

- 图片、历史记录、收藏**全部存在本地浏览器**，不上传
- 只有调用视觉模型时才把图片发出去，发给**你自己配置的服务商**
- API Key 只存在本地，插件不会把它发送到除服务商之外的任何地方
- 插件没有自己的服务器，也没有统计、埋点

## 目录结构

```
manifest.json
src/
  background.js        service worker：串起三层 + 取图注入函数
  content.js           右键标记、拖拽与粘贴入口
  tokens.css           面板与设置页共用的设计令牌
  core/
    schema.js          字段定义 + 比例推算
    vlm.js             字段层提示词 + JSON Schema
    providers.js       视觉模型注册表
    renderers.js       双引擎渲染器
    api.js             模型调用 + 设置读写
    presets.js         提示词方案的存储与切换
    naming.js          记录命名模板
    shortcut.js        快捷键组合解析
    store.js           IndexedDB 历史与收藏（含内存降级）
  panel/               结果面板
  popup/               设置页
```

## 开发

```bash
# 一键验证：14 个文件语法检查 + 130 项测试 + 6 项静态检查
node verify-all.cjs
```

单独跑：

```bash
node ratio-test.cjs          # 比例识别
node fold-test.cjs           # 折叠状态同步
node naming-test.cjs         # 记录命名
node apikey-test.cjs         # API Key 保存
node reverse-repeat-test.cjs # 重复反推
node dead-code.cjs           # 零引用的导出
node check-dom.cjs           # JS 引用了但 HTML 不存在的 id
```

测试脚本的设计原则：**改动前先确认测试能抓到旧 bug**。
每个测试文件里都有一段「把旧实现内联进来跑一遍」的用例，确保测试不是摆设。

## 已知限制

- **整页批量扫描未实现**：目前一次一张图。技术难点在虚拟滚动懒加载。
- **局部框选反推未实现**。
- **小红书的图需要特殊处理**：该站有防盗链和时效签名，取图走页面内 `no-cors` 请求。
- 部分网站会阻止扩展读取图片，此时面板会说明失败原因。
- 使用生成结果时请遵守原作品的版权与平台条款。
